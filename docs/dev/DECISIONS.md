| D39 | 2026-11-13 | The chip engine gains **test-only bus hooks** (`fm1_test_bus_write32/read32`, `fm1_test_advance_us`, `fm1_test_set_wp`) so the live chip can be conformance-tested over SPI0 without firmware and with a controlled clock. | D40 | 2026-11-13 | **Non-volatile status bits survive `powerCycle()`** for the same chip profile (new exports `fm1_flash_nv_status`/`fm1_flash_nv_restore`; WEL does not; SRP 1:0 returns to 0:0; a swapped chip starts fresh; a cycle running at power-off is treated as completing). | D41 | 2026-11-13 | `fm1_flash_events(2)` reports the last opcode the model did not cover, so a refused opcode can be identified, not just counted | Needed to resolve the quadro-fm1 case (D42); no behaviour change |
| D42 | 2026-11-13 | **`4Bh` (Read Unique ID) stays "not modelled"**: Stage A cites it only in the commands listings (Puya p.20-21, UC25HQ80 p.13); its dedicated section was not read, so its response (dummy bytes, length) is not specified by the Stage A sources. | D43 | 2026-11-13 | Live conformance expectations are the datasheets' literal values (printed protection and timing tables from `chiptests.mjs`), not read from `chipspec.mjs` or the Rust tables; the Stage A oracle is additionally replayed in full over the live engine (byte-aligned form of the transcripts) | Independent of the spec's own decisions; the replay covers what hand-written tests cannot enumerate |
| D44 | 2026-11-13 | **4Bh Read Unique ID is now modelled in the reference model** (`chipspec.mjs` `ruid.*`, `chipmodel.mjs` `#ruid`), from both datasheets' dedicated sections; each finding is labelled verified / interpretation / unspecified / unknown (FLASH-CHIPS.md). Supersedes D42 for the reference model only: the Rust engine still answers FF and the legacy profile keeps its `FM1-` pattern | Stage A extension approved after C4 showed 4Bh to be the one behaviour that changes firmware (quadro-fm1, fm1-field) |
| D45 | 2026-11-13 | The unique ID's **value** is a caller-supplied fixture (`ChipModel({ uid })`, 16 bytes in transmission order); without it the bytes are reported unknown (mask `FF`). | D46 | 2026-11-13 | Dummy bytes: Puya's are read as don't-care (interpretation, as for 0Bh); the UC25HQ80's Table-7 lists `00H` for bytes 2-4, so non-zero values there are unspecified and refused; byte 5 is don't-care | Do not infer behaviour the tables do not state; the asymmetry is the datasheets' |
| D47 | 2026-11-13 | Default oracle transcripts never contain 4Bh until the engine implements it (`gen-transcripts.mjs --with-ruid` adds opt-in 4Bh scenarios for the port); `nm.unique-sfdp` stays the id for 5Ah. | D48 | 2026-11-13 | **4Bh is implemented in the Rust chip engine** for both profiles, exactly as the reference model (D44-D46). The legacy profile's original `FM1-` answer is untouched | Approved engine port |
| D49 | 2026-11-13 | The unique-ID **fixture** is configured through `fm1_flash_uid_set(w0..w3)` / `fm1_flash_uid_clear()` (harness `flashUid`, CLI `--flash-uid`); it lives in the chip, survives power cycles and the status restore, is per chip profile (a swapped chip has none), and is never invented | The value is per device and in neither datasheet (D45) |
| D50 | 2026-11-13 | With **no fixture**, 4Bh answers `FF` and counts the read in `fm1_flash_events(3)` (`flashUidUnknownReads()`); it is neither an unspecified nor an unmodelled event. | D51 | 2026-11-13 | The byte stream cannot express every oracle case: with CS# rising before the fourth dummy byte a later byte is a dummy slot, not data. | D52 | 2026-11-13 | The build's `--test` replays the `--with-ruid` transcripts (the default scenarios plus the four 4Bh ones) through the Rust chip API and the SoC registers; the live replay does the same over the engine. | D53 | 2026-11-13 | Stage 5B scope: JavaScript only (spec, reference model, policy functions). | D54 | 2026-11-13 | The reference model never takes an outcome policy and never states post-interruption contents: it records interruption, range and indeterminate state, exposes `before`/`ifCompleted` as policy inputs, and `peek` throws `UnspecifiedBehavior` over indeterminate bytes. Synthetic fills live in `faultpolicy.mjs`, which has no model access; a test checks the separation | Physical uncertainty stays separate from synthetic outcomes; a synthetic fill must never look like a datasheet fact |
| D55 | 2026-11-13 | An explicit outcome policy (and an explicit seed for seeded fills) is mandatory; there is no default fill. | D56 | 2026-11-13 | Cut precedence: a scheduled cut fires before normal completion at the model's single choke point `#settle()`, which every entry point (including `faultState()`) runs first. Lazy detection at the next SPI access is not enough on its own; for the engine this is a 5C proof obligation (scheduled deadline in the SoC's next-event computation, recommended) | Overrides 5A decision 2 (lazy detection); the harness reads the array directly, so a pending cut must not be bypassable by not touching the chip |
| D57 | 2026-11-13 | Determinism: same flash, profile, timing, trigger, policy and seed give identical records and bytes. PRNG mulberry32, one draw per record byte (top byte), draws independent of unknown bytes, vectors frozen from an independent implementation. `prefix(f)` = first `floor(f*n)` bytes new, rest old | Reproducible failure tests; independent vectors guard against a self-confirming PRNG |
| D58 | 2026-11-13 | Fault injection disabled means unchanged: the oracle transcript hashes are pinned in a full-tier test and an armed-but-never-matching or disarmed trigger is shown equal to no trigger | Requirement 5; the 87 earlier model tests are unchanged and still pass |
| D59 | 2026-11-13 | **Approved design (5C); 5C-1 implements only the chip part, the scheduling and sync points are 5C-2:** a power cut is a scheduled event in the SoC's own event machinery (`Periph::next_event`, new `flash_cut_at`), fired at its cycle, so XIP/JIT/idle-skip/loop-skip/harness observation see it at the right time; the chip's `settle()` also never lets completion win over a due cut; a sync runs at every clock-moving export's return and at the core-1 slice boundary. | D60 | 2026-11-13 | **Approved design (5C), implemented in 5C-1 (chip part):** after a cut the bytes of the range hold the pre-image only as a labelled placeholder; the engine's indeterminate list is the authority and survives any fill; the harness applies explicit synthetic bytes from `faultpolicy.mjs`; the engine never computes a fill; reads of listed bytes are counted; the cut is terminal for the machine (`power_cut`, never `halted`) | Keeps physical uncertainty separate from synthetic outcomes in the engine (requirements 2, 4) |
| D61 | 2026-11-13 | 5C-1: the Rust chip captures the pre-image of the affected range **at accept** (before the array changes, D33) and what a normal completion would produce (right after), only while journaling is on (`arm_fault` or `set_fault_injection`); a cut keeps both as inputs, marks the ranges indeterminate and never computes an outcome. `sync_cut` writes the pre-image back as a labelled placeholder; there is no fill in the engine | Requirements 2-4 of 5C-1: pre-image preserved, indeterminate tracked beside the array, fills stay harness policies |
| D62 | 2026-11-13 | 5C-1 deliberate differences from the model: times in cycles with the cut clamped before the end; a powered-off chip answers `0xFF` and counts instead of throwing; `power_cut()` refuses (`fault.not-enabled`) a cycle accepted before journaling was on; `power_cycle()` after a cut is ignored and counted; reads of indeterminate bytes return the array byte and are counted | The engine has no exceptions and a byte stream, and must not fake a journal it did not take |
| D63 | 2026-11-13 | The model is the oracle for the chip state: `gen-transcripts.mjs --with-fault` (opt-in; default transcripts byte-identical, pinned) adds 296 interrupted-operation scenarios; the Rust chip driver replays them (3,220 fault steps, 0 mismatches); the register driver skips them until 5C-2. `build.mjs --test` passes the flag | One transcript, two implementations, as for 4Bh (D52) |
| D64 | 2026-11-13 | 5C-2: the cut deadline is `Periph::flash_cut_at`, an input of `next_event()`; the chip's accept schedules it (`flash_cut_schedule` after every flash write, firing at once if already due); the event calls `sync_flash_cut` (chip settled with the cut first, placeholder, XIP refresh, terminal flag). `run_blocks`/`run_dual`/`run_cpu1` stop with `POWER_CUT`; `Machine.power_cut` is a state of its own, never `halted`; terminal: a chip restore does not restart the cores | Requirement 1-3, 5, 6 of 5C-2. | D66 | 2026-11-13 | 5C-2: the register driver of the oracle replays the interrupted-operation scenarios too (3,220 fault steps, 0 mismatches); a cut due at the accept is detected at the accept (the SoC fires it in the write path), every other at the replay's clock move, like the model | One transcript now checks the model, the chip and the SoC |
